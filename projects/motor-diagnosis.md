# Bind Edge AI — 모터 상태 모니터링 시스템

[← 포트폴리오 목록](../README.md)

도서·섬 지역 회전설비의 진동·음향 데이터를 수집하고, 운영자가 이상 징후와 판정 근거를 원격으로 확인할 수 있도록 개발 중인 4인 팀 프로젝트입니다. 프로젝트 기획과 백엔드 전체 개발을 맡아 데이터 수집부터 이벤트 관리, 운영자 검수·알림, 백업·복구까지 구현했습니다.

- **개발 상태:** 진행 중
- **담당 역할:** 프로젝트 기획 및 백엔드 전체 개발
- **백엔드·운영 기술:** Python, SQLite, AWS EC2, Caddy, systemd
- **팀 저장소:** [MotorDiagnosis](https://github.com/ckdudwns/MotorDiagnosis)
- **소개 범위:** 2026년 9월 8일 작품 소개 보고서에 정리한 기존 구현과 검증 기록

## 전체 흐름과 담당 범위

도서 지역의 접근성과 통신 환경을 고려해, 현장에 직접 방문하지 않아도 설비의 측정값과 이상 이력을 확인할 수 있는 서비스를 기획했습니다.

```text
센서·장치의 진동·음향 측정과 전송
    ↓
서버의 입력 검증·중복 확인·저장
    ↓
분석 결과 연동·이상 이벤트 관리
    ↓
대시보드 조회·운영자 검수·알림
```

센서·AI 담당자와 입력 규격을 맞추고, 서버가 데이터를 접수·저장한 뒤 분석 결과를 운영 화면과 이벤트로 연결하는 부분을 담당했습니다. 백업·복구와 계정·장치 인증도 백엔드 담당 범위에 포함됩니다.

위 흐름은 시스템의 연결 구조입니다. 실장치 요약 데이터의 서버·화면 연결 기록은 확보했으며, RF66 원시 진동 데이터의 연속 수집·분석은 보고서 시점에 추가 검증이 필요한 단계였습니다.

## 구현한 백엔드 기능

| 영역 | 구현 내용 |
|---|---|
| 데이터 수집·저장 | 센서 입력 검증, 데이터 저장, 재전송 중복 방지, 같은 식별자의 내용 충돌·순서 역전 거부 |
| 이상 이벤트 관리 | 유효한 연속 3구간을 기준으로 RF66 이벤트 생성·유지·해제, 누락·품질 불량·모델 변경 구분 |
| 계정·장치 인증 | 사용자 계정과 장치의 접근을 확인하는 인증 처리 |
| 운영자 기능 | 대시보드 조회, 이벤트 검수, 알림 |
| 운영·복구 | 관련 DB·모델·설정 백업, 파일 해시·SQLite 무결성 확인, 별도 폴더 복구 검사, 점검·백업 예약 |

## 검증 기록과 후속 과제

아래는 **2026년 9월 8일 작품 소개 보고서 기준**입니다. 구현한 기능, 검사 기록, 실제 장비 연결 범위를 나누어 정리했습니다.

| 구분 | 확인한 내용 |
|---|---|
| 백엔드 검사 | 14개 모듈, 총 234개 중 **222개 통과·12개 건너뜀**, 실패·오류 0건. 검사 기준 커밋: `380f112` |
| 서버 실행 | EC2 서비스 실행 및 백업 후 서비스 상태 정상 확인 기록 |
| 백업·복구 | 수동 백업 무결성 확인 및 별도 폴더 복구 검사 완료 기록 |
| 실장치 연동 | 기존 요약 데이터의 서버·화면 연결 기록 확보 |
| 원시 진동 분석 | 서버 구현과 검사 기록 확보. 당시 EC2 점검에서는 원시 입력이 수신되지 않아 실장치 연속 수집·분석 검증은 남아 있었음 |

검사 결과는 해당 시점과 범위에 한정합니다. 현재 최신 코드의 전체 테스트 결과나 현장 설비의 진단 성능을 의미하지 않습니다.

다음 검증·개선 과제로 정리한 항목은 다음과 같습니다.

1. **실장치 원시 데이터 연동:** 연속 수집부터 분석 결과 확인까지 실제 장비로 검증
2. **통신 장애 대응:** 장시간 단절과 복구 과정에서 재전송·중복 처리 확인
3. **다중 장치 운영:** 장치 증가에 따른 저장 용량과 데이터 보관 정책 개선

<summary><strong>1. 재전송에도 중복되지 않는 데이터 수집</strong></summary>

통신 응답이 유실되면 장치가 이미 전송한 데이터를 다시 보낼 수 있습니다.

장치·부팅 식별자·구간 순번으로 원시 데이터를 식별하고, 동일한 내용의 재전송은 기존 접수 결과를 반환하도록 구성했습니다. 같은 식별자에 다른 내용이 들어오거나 순서가 역전된 입력은 거부합니다.

저장 완료와 분석 완료를 구분하고, DB 저장 실패 시 분석 결과와 연속 판정 상태가 진행되지 않도록 처리했습니다.

<summary><strong>2. 이상 신호와 운영 이벤트의 분리</strong></summary>
